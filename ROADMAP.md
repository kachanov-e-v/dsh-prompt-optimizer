# ROADMAP

Планы и направления развития `dsh-prompt-optimizer`. Приоритеты: **P1** —
надёжность и установка, **P2** — качество повседневного UX, **P3** —
расширения, без которых плагин остаётся полноценным.

## Принятые решения

- **Правила работы включены всегда** — без UI-переключателя: иначе поведение
  режимов LLM и «Шаблон» расходится. Язык блока совпадает с языком черновика.
- **Пункты о русском языке есть только в блоке `ru`** (решение пользователя):
  в `en` / `zh` остаются 5 правил, а язык общения задаёт сам черновик; иначе в
  англоязычном промпте появлялось бы требование отвечать по-русски.
- **Правила хранятся в двух местах** (`STANDING_RULES` в `index.js` и `rules` в
  `RU` / `EN` / `ZH` в `client.js`) из-за разделения бандла на половины;
  расхождение обнаруживает `npm run check`.
- **Автоматическая проверка — один скрипт на чистом Node**, без тест-раннера и
  зависимостей; полноценные тесты на `node:test` остаются в P1.
- **Сборка и TypeScript не вводятся** ради предсказуемой установки бандла.

## Ближайшее — P1

- [ ] **Тесты без внешних зависимостей** (`node:test`): `buildPrompt` /
      `detectIntent` / `detectLanguage` и Host-маршрут с замоканным `ctx.llm`
      (успех, таймаут, `NO_MODEL`, слишком большое тело). Шаблон, правила и
      системный промпт уже покрыты `test/rules-check.mjs`; остаются маршрут и
      HTTP-коды.
- [ ] **Валидация конфигурации** (`provider`, `model`, `timeoutMs`, `maxTokens`)
      до вызова модели и понятная ошибка в UI вместо `LLM_ERROR`.
- [ ] **Отмена запроса** по повторному клику/кнопке Stop и явное состояние
      «таймаут» с возможностью повторить, а не только автоматический шаблон.
- [ ] **GitHub Release с тегом `vX.Y.Z` и `.tgz`-ассетом**: стабильная
      install-ссылка и воспроизводимая версия вместо `master.tar.gz`.
- [ ] **CI для упаковки**: `node --check`, разбор JSON/SVG, `npm pack --dry-run`
      и проверка, что в пакет попали `index.js`, `client.js`, patch, locale и
      icon.
- [ ] **Стратегия обновления GitHub-установок**: сейчас git/архив не входят в
      `listVersions`; нужен документированный remove + add или переход на npm.

## Качество UX — P2

- [ ] Показывать активную модель и состояние запроса в тултипе/подписи.
- [ ] Потоковый предпросмотр переписывания в поле ввода вместо ожидания
      полного ответа.
- [ ] Раздельные системные промпты LLM-пути для кода, анализа и вопросов —
      сейчас локальный шаблон учитывает intent, а LLM-путь использует общий.
- [ ] Лучшая обработка очень длинных черновиков: чанкинг/суммаризация и явное
      предупреждение о лимите до отправки.
- [ ] Видимое текстовое уведомление (сейчас только точка с `title`; добавлен
      `aria-label`, но нужен полноценный статус).
- [ ] **Расширить `detectIntent` русскими терминами** («функция», «js»,
      «переменная», «верстка»): сейчас «Напиши функцию на js» классифицируется
      как `create` и получает роль продуктового специалиста вместо инженерной.
- [ ] **Сокращать блок правил для intent `question`/`analyze`** или переносить
      его в конец: 7 пунктов уместны для задач, но тяжелы для короткого вопроса.
- [ ] Опция «скопировать результат, не заменяя черновик» для сценариев, где
      улучшенный промпт нужен в другом месте.

## Расширения — P3

- [ ] **Полный русский язык в коде**: комментарии в `index.js` / `client.js` и
      тексты ошибок маршрута пока на английском, хотя правило 5 требует русского
      во всём проекте (коды ошибок и имена идентификаторов остаются как есть).
- [ ] Пользовательские стилевые пресеты и собственный системный промпт.
- [ ] Публикация в npm (`private: false`, `publishConfig`, trusted publishing),
      чтобы заработали обновления из Plugin Manager, затем — в маркетплейс DSH.
- [ ] История промптов и избранное в боковой панели (вне ядра плагина).
- [ ] Опциональная телеметрия использования шаблона/LLM — только по явному
      согласию и выключена по умолчанию; не является приоритетом.
