# dsh-prompt-optimizer

Плагин DeepSeek Harness (DSH), который добавляет в строку инструментов композера
кнопку **«Оптимизатор промптов»** (Prompt Optimizer). Он переписывает черновик
запроса в качественный, структурированный, профессиональный промпт — либо
моделью, выбранной пользователем, либо детерминированным локальным шаблоном, —
и записывает результат обратно в поле ввода.

- **Пакет:** `dsh-prompt-optimizer` (версия 3.3.0)
- **Установка:** GitHub — `https://github.com/kachanov-e-v/dsh-prompt-optimizer`
- **Тип:** DSH Cordis-бандл (`host` + `client`)
- **Слот UI:** `conversation.input.left`
- **Лицензия:** MIT

## Что делает

Кнопка располагается в левой части строки инструментов композера, рядом с
остальными компактными элементами управления. У неё два режима, переключаемых
маленьким чипом рядом:

| Режим | Поведение |
|-------|-----------|
| **LLM** (по умолчанию) | Отправляет черновик на Host-маршрут `/dsh-prompt-optimizer/optimize`, который стримит переписывание через настроенную LLM (`ctx.llm`, используется модель по умолчанию). Модель строит структуру промпта и оставляет маркер `<!--WORKING-RULES-->`; сам блок правил вставляет Host, поэтому модель не может его переписать, сократить или потерять. |
| **Шаблон** | Переписывает черновик локально по детерминированному шаблону: роль, задача, требования, правила работы, формат ответа и критерии качества. Без сетевого запроса, без токенов. Поддерживает русский, китайский и английский черновики. |

Повторный клик по основной кнопке возвращает исходный черновик. Выбранный
режим сохраняется в `localStorage`.

## Правила работы в улучшенном промпте

Каждый улучшенный промпт — и в режиме **LLM**, и в режиме **Шаблон** — содержит
раздел **«Правила работы»** (`Working rules` для английского черновика,
`工作规则` для китайского). Порядок разделов: роль → задача → требования →
правила работы → формат ответа → критерии качества. Отдельного раздела
«Контекст» нет: он всегда дублировал правила и не нёс контекста самой задачи.

Правила (9 пунктов для русского черновика):

1. **Документация вместе с кодом.** `AGENTS.md` — правила и соглашения для
   агентов, `ROADMAP.md` — статус, приоритеты и следующий шаг, `README.md` —
   установка, использование и архитектура. У каждого файла своя роль:
   дублировать один текст в трёх местах нельзя, отсутствующий файл создаётся в
   той же задаче.
2. **Знание в репозитории, а не в переписке.** Текущее состояние, решения, их
   причины, известные проблемы и следующий шаг фиксируются в репозитории, чтобы
   новая сессия продолжила работу без истории чата. Решение без причины
   считается незафиксированным.
3. **Не угадывать.** Не выдумывать API, пути, версии и цифры; при нехватке
   данных — до трёх точных вопросов; на развилке — варианты и явная рекомендация
   лучшего с обоснованием; факт отличается от предположения.
4. **Ответы и вопросы — на русском языке.**
5. **Весь проект — на русском.** Документация, интерфейс, комментарии, сообщения
   об ошибках, коммиты и правила. Исключения — идентификаторы кода, имена
   библиотек и внешних API, служебные файлы инструментов.
6. **Инженерные конвенции.** Стиль и соглашения языка и фреймворка, совместимость
   версий, обработка ошибок и граничных случаев, никаких секретов в репозитории
   и логах.
7. **Отчёт по факту, четыре строки.** Проверено (что и какими командами) /
   Не проверено / Риски / Следующий шаг. Непроверенное не называется готовым.
8. **Границы задачи.** Делается ровно запрошенное: без попутного рефакторинга,
   новых зависимостей и изменений публичных контрактов, формата данных и
   лицензии без явного согласия.
9. **Блокер — стоп.** Нет доступа, противоречивые требования, риск потери данных:
   работа останавливается, блокер и варианты описываются. Ограничения не
   обходятся, проверки не отключаются ради «зелёного» статуса.

Для английского и китайского черновиков пункты 4 и 5 не включаются: в блоке
остаются 7 правил, а язык ответа задаёт сам черновик.

Список правил хранится в двух местах — `STANDING_RULES` в `index.js` и массивы
`rules` в объектах `RU` / `EN` / `ZH` в `client.js` — и должен совпадать
дословно. В LLM-режиме тексты правил в модель не отправляются вовсе: модель
ставит маркер `<!--WORKING-RULES-->`, а Host подставляет по нему готовый блок
(или добавляет его в конец, если модель маркер потеряла).

## Поведение при ошибках

Если модель недоступна (нет модели по умолчанию, отсутствует LLM-сервис,
ошибка провайдера, таймаут, отмена запроса, отказ gate) или ответ обрезан
лимитом токенов (`TRUNCATED`), плагин автоматически применяет локальный шаблон,
показывает предупреждающую точку с причиной и — при `NO_MODEL` / `NO_LLM` —
переключает режим на **Шаблон**. Если пользователь изменил черновик, пока модель
работала, результат модели не затирает новые правки.

## Установка из GitHub

Плагин — обычный npm-пакет с `dsh.bundle.patch`, поэтому DSH устанавливает его
непосредственно из репозитория. Никакой сборки не требуется.

### Через Plugin Manager (рекомендуется)

1. Откройте **Plugins** в Web UI DSH.
2. Нажмите установку плагина по URL.
3. Вставьте один из адресов:
   - `https://github.com/kachanov-e-v/dsh-prompt-optimizer`
   - `github:kachanov-e-v/dsh-prompt-optimizer`
4. Подтвердите установку, включите бандл, если он выключен, и перезагрузите
   страницу (`F5`), чтобы клиентский модуль был подхвачен.

### Через CLI

`dsh plugin` передаёт аргументы в pnpm внутри каталога профиля:

```bash
# GitHub-спецификация (нужен рабочий Git)
dsh plugin --profile desktop add github:kachanov-e-v/dsh-prompt-optimizer

# или явная HTTPS-спецификация
dsh plugin --profile desktop add \
  https://github.com/kachanov-e-v/dsh-prompt-optimizer.git
```

### Если Git недоступен: архив GitHub

Этот вариант не вызывает Git и работает даже там, где сломан TLS-бэкенд Git:

```bash
# стабильная версия 3.3.0 (тег, неизменяемый архив)
dsh plugin --profile desktop add \
  https://github.com/kachanov-e-v/dsh-prompt-optimizer/archive/refs/tags/v3.3.0.tar.gz

# последняя версия ветки master
dsh plugin --profile desktop add \
  https://github.com/kachanov-e-v/dsh-prompt-optimizer/archive/refs/heads/master.tar.gz
```

Архив тега ставит неизменяемую версию, архив `master` — последний снимок
ветки. Для обновления повторите установку с новым тегом.

### Windows: `schannel: SEC_E_NO_CREDENTIALS`

Если Git при установке из GitHub пишет `schannel: AcquireCredentialsHandle
failed: SEC_E_NO_CREDENTIALS`, переключите TLS-бэкенд Git на OpenSSL:

```bash
git config --global http.sslBackend openssl
```

После этого повторите установку. Альтернатива без изменения Git — архивная
ссылка выше.

### Локальная разработка

```bash
dsh plugin --profile desktop add "C:\путь\к\dsh-prompt-optimizer"
```

`private: true` в `package.json` запрещает случайную публикацию в npm, но не
мешает установке из Git, архива или локального каталога.

### Обновление и удаление

Установки из Git/архива не входят в автоматические обновления registry-пакетов:
повторите `add` с новой ссылкой или удалите и установите заново.

```bash
dsh plugin --profile desktop remove dsh-prompt-optimizer
```

## Использование

1. Откройте сессию в Web UI DSH.
2. Посмотрите на левую часть строки инструментов композера — там будет
   **✨ Улучшить** плюс маленький чип **LLM / Шаблон**.
3. Введите черновик запроса в поле ввода.
4. Нажмите **Улучшить**. В режиме LLM кнопка показывает **Улучшаю…**, пока
   выполняется запрос; в режиме шаблона переписывание мгновенное.
5. Поле ввода теперь содержит улучшенный промпт. Нажмите кнопку ещё раз, чтобы
   вернуть исходный черновик.
6. Используйте чип для переключения режима. Выбор запоминается между сессиями.

Язык интерфейса следует активной локали DSH (`ru`, `zh`, `en`).

## Контракт Host-маршрута

`POST /dsh-prompt-optimizer/optimize`

Тело запроса (JSON):

```json
{ "text": "черновик", "language": "ru" }
```

- `text` — обязательно, непустая строка, до 20 000 символов.
- `language` — `"ru"`, `"zh"` или `"en"` (по умолчанию `"en"`).

Ответ (JSON):

```json
{ "ok": true, "text": "улучшенный промпт", "provider": "...", "model": "..." }
```

Ошибки возвращаются как `{ "ok": false, "code": "...", "error": "..." }` со
статусами `400 / 401 / 403 / 405 / 409 / 413 / 415 / 502 / 504`.

Безопасность: проверка same-origin, Host request gate (`connection.requestRejection`),
ограничение размера тела (`128 KiB`) и длины текста.

## Разработка

- Host-половина: обычный ESM, без шага сборки. Экспортирует `apply(ctx, config)`
  и `inject = ['webServer']`.
- Client-половина: фабрика `window.__ModuleLoader__.load`, React из таблицы
  модулей браузера, без JSX-трансформации. Вся разметка и CSS самодостаточны.
- Логика локального шаблона находится в `buildPrompt` / `detectIntent` /
  `detectLanguage` / `cleanDraft` внутри `client.js`.
- Раздел «Правила работы» продублирован по половинам бандла: `STANDING_RULES`
  в `index.js` и `rules` в `RU` / `EN` / `ZH` в `client.js`. Правка правил без
  правки второй половины — ошибка: список должен совпадать дословно и по
  порядку.
- В LLM-режиме модель блок правил не пишет: она оставляет маркер
  `<!--WORKING-RULES-->`, а `withWorkingRules` в `index.js` подставляет по нему
  канонический раздел (в конец — если маркер потерян). Поэтому правка правил
  влияет на оба режима сразу, без переобучения промпта модели.
- Проверки перед коммитом: `node --check client.js && node --check index.js`,
  разбор `package.json` и `locale/*.json`, `npm run check` (собирает обе
  половины в песочнице: разделы и порядок шаблона без «Контекста», 9 правил для
  `ru` и 7 для `en` / `zh`, совпадение правил и заголовков между половинами,
  отсутствие правил в промпте модели, вставку блока по маркеру, определение
  языка и намерения), `npm pack --dry-run --json`.
- Автотестов на `node:test` пока нет — это пункт P1 в [ROADMAP.md](ROADMAP.md).

## Конфигурация

Бандл принимает необязательный объект `config` в строке плагина:

```yaml
- id: dsh-prompt-optimizer
  config:
    provider: deepseek-official   # переопределить LLM-провайдера
    model: deepseek-v4-flash      # переопределить LLM-модель
    timeoutMs: 45000              # таймаут запроса, 3000..120000
    maxTokens: 1200               # ограничение вывода, 128..4000
```

Если `provider`/`model` не указаны, используется текущая модель по умолчанию.
