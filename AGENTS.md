# AGENTS.md

Руководство для AI-агентов, работающих с `dsh-prompt-optimizer`.

## Проект

- Плагин DSH (DeepSeek Harness) в виде Cordis-бандла.
- Две половины: `index.js` (Host, ESM, `apply(ctx, config)` + `inject`) и
  `client.js` (фабрика браузера `__ModuleLoader__`, React из таблицы модулей
  браузера).
- Без шага сборки, без TypeScript, без тест-раннера. Только чистый JavaScript;
  единственная автоматическая проверка — `test/rules-check.mjs` на чистом Node.
- UI внедряется в слот `conversation.input.left`.

## Обязательные правила

Правила действуют в каждой сессии. Та же суть зашита в раздел «Правила работы»
улучшенных промптов (`STANDING_RULES` в `index.js` и `rules` в `RU` / `EN` /
`ZH` в `client.js`); там формулировки короче, а пункты о русском языке есть
только в блоке `ru`. Проверяется не совпадение с этим файлом, а совпадение
половин бандла между собой.

1. **Документация обновляется вместе с кодом.** `AGENTS.md` — правила и
   соглашения, `ROADMAP.md` — статус, приоритеты и следующие шаги, `README.md` —
   установка, использование, архитектура и контракт маршрута. Изменение кода без
   правки этих файлов считается незавершённым.
2. **Бесшовность между сессиями.** Продолжить работу должна новая сессия без
   истории прошлых чатов: состояние, принятые решения и их причины, известные
   проблемы и следующий шаг фиксируются в репозитории, а не в переписке.
3. **Не угадывать.** При нехватке данных — до трёх точных вопросов. На развилке —
   перечень вариантов и явная рекомендация лучшего с обоснованием.
4. **Только русский язык.** Ответы, вопросы, планы и отчёты — на русском.
5. **Проект полностью на русском.** Документация, UI-тексты, комментарии,
   сообщения, коммиты и правила; по-английски — только технические
   идентификаторы, имена внешних API и строки, которые сравниваются в коде.
   Текущие исключения (английские комментарии и тексты ошибок в `index.js` /
   `client.js`, локали `en` / `zh`) закрывает пункт P3 в `ROADMAP.md`.
6. **Проверенные практики.** Маленькие проверяемые шаги, обработка ошибок и
   граничных случаев, отсутствие секретов в репозитории, автоматические проверки
   до отчёта о готовности.
7. **Отчёт по факту.** Проверено (что и какими командами) / Не проверено / Риски /
   Следующий шаг; непроверенный результат не называется готовым.
8. **Границы задачи.** Делать ровно запрошенное: без попутного рефакторинга,
   новых зависимостей и изменений публичных контрактов, формата данных и
   лицензии без явного согласия.
9. **Блокер — стоп.** Нет доступа, противоречивые требования, риск потери данных:
   остановиться, описать блокер и варианты. Не обходить ограничения и не отключать
   проверки ради «зелёного» статуса.

## Как продолжить работу в новой сессии

1. Прочитать `AGENTS.md`, `ROADMAP.md` и `README.md` — там текущее состояние.
2. `git log --oneline -5` и `git status` — что уже сделано и что не закоммичено.
3. `npm run check` — убедиться, что проверки проходят до начала правок.
4. Взять верхний незакрытый пункт `ROADMAP.md` (или задачу пользователя) и
   отметить в `ROADMAP.md`, что работа начата.
5. По завершении: обновить документацию, прогнать проверки, зафиксировать
   следующий шаг в `ROADMAP.md` и сообщить в отчёте, что именно проверено.

## Соглашения

- Обе половины должны быть без зависимостей (никаких `require` пакетов Harness).
- Host-половина должна декларировать `inject` для каждого используемого сервиса
  (`webServer`, опционально `llm`/`agentDefaultModel`/`connection` через
  `ctx.get`).
- Client-половина должна возвращать `{ inject, apply }` и регистрировать слоты
  через `ctx.slots.inject` + `ctx.slots.register`.
- Стилизация только токенами `--dsw-alias-*`; буквальные цвета — только для
  графики (иконка).
- Локализация UI по префиксу языка (`ru` / `zh` / `en`), не по точному id
  локали, так как DSH использует региональные id вроде `ru-RU`.
- Тела запросов ограничены и валидируются на стороне Host.
- Никогда не вызывать модель из клиента; всегда через Host-маршрут.
- Раздел «Правила работы» продублирован: `STANDING_RULES` в `index.js` и `rules`
  в `RU` / `EN` / `ZH` в `client.js`, на трёх языках (9 пунктов для `ru`,
  7 для `en` / `zh` — пункты о русском языке только в `ru`). Править обе
  половины сразу, дословно и в том же порядке — иначе `npm run check` падает.
- В LLM-режиме модель не пишет блок правил: она оставляет маркер
  `RULES_MARKER` (`<!--WORKING-RULES-->`), а `withWorkingRules` в `index.js`
  подставляет канонический раздел. Менять контракт маркера — только вместе с
  текстом системного промпта и проверкой.

## Работа с кодом

- Редактировать `client.js` / `index.js` напрямую; шага компиляции нет.
- Проверка синтаксиса: `node --check client.js && node --check index.js`.
- Функциональная проверка: `npm run check` — собирает обе половины в песочнице и
  сверяет разделы и порядок шаблона (без «Контекста»), число правил (9 для `ru`,
  7 для `en` / `zh`), совпадение правил и заголовков между половинами,
  отсутствие правил в промпте модели, вставку блока по маркеру, определение
  языка и намерения.
- Проверка JSON: разбор `package.json` и `locale/*.json`.
- SVG: должен разбираться как XML (`[xml](Get-Content icon.svg)`).
- Проверка состава пакета: `npm pack --dry-run --json` (кэш npm держать внутри
  рабочего каталога, иначе sandbox может запретить запись).
- Бандл связан с профилем из этого каталога; после правок переустановить через
  `plugin_manager install_bundle` (или удалить + установить) и перезагрузить
  страницу.
- Для проверки GitHub-установки использовать архив
  `.../archive/refs/heads/master.tar.gz`: он не зависит от TLS-бэкенда Git.
  Прямая git-спецификация на Windows может требовать
  `git config --global http.sslBackend openssl`; не менять глобальный конфиг
  без явного согласия пользователя.

## Не делать

- Не добавлять JSX или TypeScript — client-половина выполняется `__ModuleLoader__`
  как чистый JS.
- Не импортировать пакеты клиента Harness (`@deepseek-ai/dsh-client-*`) из
  client-половины; использовать сервисы `ctx` и `host.call`.
- Не хранить секреты в `config` или в репозитории.
- Не менять правила работы только в одной половине бандла и не переводить их на
  другой язык в одном из путей: расхождение ломает сборку проверки.
- Не коммитить ad-hoc тестовые скрипты и артефакты сборки.

## Релиз

- Поднять `version` в `package.json` и синхронизировать версию в README.
- Прогнать проверки из раздела «Работа с кодом» и `npm pack --dry-run`.
- Переустановить бандл в профиле и проверить регистрацию слота через
  `cordis_inspect_query` (`Slots.listSubTree`, корень `conversation.input.left`).
- Закоммитить, поставить тег `vX.Y.Z`, запушить ветку `master` и тег.
- Проверить установку из GitHub по архивной ссылке тега/ветки (см. README) и
  сообщить, если для прямой git-спецификации нужен `http.sslBackend=openssl`.
